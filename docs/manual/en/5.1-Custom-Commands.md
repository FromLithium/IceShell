# 5.1 Custom Commands

With the IceShell API, you can register your own commands as IceShell internal commands. It is also recommended for contributors of the project to follow this documentation for guidelines on new built-in commands.

## Structure

A custom command should be in this structure:

```csharp
internal static class MyCommand
{
    internal static void RegisterTo(IRegistryCommandDispatcher dispatcher)
    {
        new CommandBuilder("mycommand", Routine)
            // ..arguments..
            // ..options..
            .Build(dispatcher);
    }

    private static CommandResult Routine(IShell shell, ICommandExecutor executor, CommandContext context)
    {
        // Command logic...
    }
}
```

## Basics

Commands are uniquely identified by their command ID, which will also be registered as their first alias. Users reference to commands by using command aliases, and one command may have multiple aliases.

One ID may only be assigned to one command at the same time, and commands may only have one ID.

One alias may only be assigned to one command at the same time, but commands may have multiple aliases.

### Execution Result

Command routines returns `CommandResult` - which is a type that includes the _exit code_ and the _error code_ of an integrated command execution.

`CommandResult` type comes with numerous `With`- methods to help create instances of `CommandResult` with an error code or with an exit code, even wih custom messages.

For a reference of integrated error codes, see [Error Codes](4-Error-Codes.md).

## Parameters

Commands supports generally three types of parameters defined:

- Switch options, an option without a value `/S`

- Option parameters, an option with a value (`/O:value`)

- Value parameters, a value specified by its position in the command line

For detailed information on the syntax of these parameters, see [Syntax](2-Syntax.md).

With `CommandBuilder`, it is easy to define these parameters:

```csharp
new CommandBuilder("mycommand", Routine)
    .SwitchOption('S') // Define a switch option
    .ValueOption('V') // Define an option parameter
    .ValueParameter("parameter") // Define a value parameter
    .Build(dispatcher);
```

To retrieve arguments, use the `CommandContext` passed to your routine function. The `CommandContext` type provides several helper methods to retrieve arguments:

```csharp
context.GetSwitch('S'); // Get the state of a switch option
context.GetOptionValue('V'); // Get the value of an option parameter
context.GetValue("parameter"); // Get the value of a value parameter.
```

Switch options and option parameters are uniquely identified by a single letter which is used by the user to specify such option; while value parameters are uniquely identified by a reference name which displays in help messages.

You cannot have any two options with the same identifier letter, even if one of the two is a switch option and the other is an option parameter. The same goes for the reference name of the value paremeters.

## Registering

Provided that you follow the structure above, now you can simply do this to register the command to a shell instance:

```csharp
MyCommand.RegisterTo(shell.Dispatcher);
```

Or, if you are registering at the initialisation method of a module, then use:

```csharp
MyCommand.RegisterTo(dispatcher);
```

## Help Messages

IceShell automatically generates localised help message IDs for each command, and each parameter of that command. This includes:

- `command.<command-name>.description`: The command description summary.

- `command.<command-name>.option_<letter>.description`: The description summary for an option - either switch option or option parameter.

- `command.<command-name>.value_<referenceName>.description`: The description summary for a value parameter.

## Legacy commands

Some commands are registered in the legacy annotated way via the `AnnotatedCommandRegistry`. This is no longer recommended, and annotated commands will not
support any new features. Plus, it is not compatible with NativeAOT nor trimming.

It is recommended that you port your legacy annotated command to the new command registry system.

# 2. 语法

IceShell 的命令语法是受 Windows 命令提示符和 MS-DOS 语法而启发。除非另有注明，否则所有 IceShell 内部命令均使用此语法。

外部命令不适用此命令语法。请尝试执行外部命令时使用 `/?`、`-?` 或 `--help` 参数来获取该外部命令的语法信息。
IceShell 并不能翻译外部命令的语法；执行外部命令时，IceShell 只会将您输入的命令的参数拆分后直接传入外部命令。

命令语法中的所有符号无一例外都是半角符号。

命令语法如下所示：

```plain
command /O /V:value /Q:"quoted value" -- value0 value1 value2
```

## 选项

选项分为*开关选项*和*选项参数*。所有选项都是选填的，且默认都有默认值。

开关选项，顾名思义，就是一个开关。只要填上了这种选项，就会打开这个开关；而如果没有填上，那么这个开关就是关上的。

而选项参数则是需要指定值的选项。

选项由一个半角前斜杠指定，其后是一个英文字母或符号来指定具体选项，并且其后还可以写上半角冒号（`:`）并在后方写上一个值。所有选项的指定符字母都区分大小写。

如果某个选项被用引号包围（注：不包括值被引号包围的选项参数，如`/V:"value"`），则会被 IceShell 视作只是一个值参数并被按值参数传递（比如说，你需要传递一个 Unix 路径）。打个比方，下面的这一个选项就会被当作值参数传递：

```text
"/O:value"
```

除此之外，所有位于选项结束指定符（即 `--`）之后的选项一样会被忽略并当作值参数传递。

### 选项参数

选项参数的值可以打引号，也可以不打引号。

```plain
/U:unquoted-value
/Q:"quoted value"
```

打引号的值内可以包含空格，而不打引号的值则不允许包含空格。命令本身并不会得知值是否打了引号；这个信息只用于解析参数。（可变参数命令除外，因为这些命令需要自行解析值参数）

如果指定选项参数，就必须指定值，反之就不能指定选项参数。不允许指定没有值的选项参数。

选项参数的值遵循[值参数](#standard-values)的原则。

### 开关选项

开关选项就犹如命令的一个“开关”，如果被指定则会打开这个开关，而没有指定的话则会让该开关处于关闭状态。

```plain
/S
```

不允许为开关选项指定值。只能指定没有值的开关选项，或者干脆不指定开关选项。

## 值参数

值参数以其在命令中的顺序被指定，并且可以被打引号或不打引号。IceShell 并不向命令透露值参数是否打了引号（注：可变参数命令除外，这种命令需要自行解析值参数），因为值参数打不打引号对于命令来说不是很重要。

### 不打引号的值参数

值参数可以以不打引号的形式指定。在这种情况下，值参数不能包含空格，因为空格会将这种值参数一分为二。

```plain
unquoted-value
^------------^
 视为一个值参数

unquoted value
^------^ ^---^
 视为两个不同的值参数

unquoted value yay!
^------^ ^---^ ^--^
 视为三个不同的值参数

以此类推……
```

### 打了引号的值参数

打引号的值参数是值被半角双引号包围的值参数。如果需要在值参数内包含如半角双引号等特殊符号，可以使用半角反斜杠来进行转义（如需使用半角反斜杠则输入两个半角反斜杠即可）。

打引号的值可以包含空格。

```plain
"\\" -> \
"\"" -> "
"\"对你一见钟情了！\"" -> "对你一见钟情了！"
"離さない 捕まえるから" -> 離さない 捕まえるから
```

## 无限扩展的值参数

某些命令的最后一个值参数是无限扩展的值参数，它可以在不打引号的情况下犹如打引号一样包含空格。你仍然可以正常对其打引号，在此情况下这种值参数将会被视为普通的打引号的值参数。

```plain
greedy-command /O 无    限    扩    展
                  ^-----------------^
                   这个值不会被一分为二
```

## 可变值参数命令

某些命令的语法复杂到需要自行解析值参数。这种情况下，IceShell 会附带值参数是否被打引号的信息直接将值参数按顺序传递给命令以供解析。

详见 [API](5-API.md#Variable-value-commands) 中有关可变值参数命令的信息。

可变值参数的基本语法仍然适用[普通值参数](#standard-values)的原则。
